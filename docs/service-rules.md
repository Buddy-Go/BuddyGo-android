# 운동메이트 서비스 규칙 정의서

## 0. 문서 안내

이 문서는 운동메이트 앱의 서비스 규칙을 한곳에 모은 것으로, 서버 로직·API 명세·화면 수정의 기준이다.기준 화면은 **운동메이트 앱v4** 와이어프레임이고(스크린샷은 `docs/design/screens/`), 와이어프레임과 이 문서가 다르면 이 문서를 따른다. 문서 안의 프레임 번호는 v4 기준이다. (v3 번호와의 대응은 `docs/project-rules.md`의 대응표 참고)

- 규칙이 있는 로직(신청 수락, 마감, 체크인, 평가, 매너온도, 노쇼)은 모두 서버에서 판정한다. 앱은 결과만 보여준다.
- **(가정)** = 와이어프레임·설명에 없어서 임시로 정한 규칙. 팀 확인 후 확정한다.
- **(논의)** = 팀이 이야기해서 정하기로 한 항목.
- 아래 숫자는 바뀔 수 있으니 코드에 직접 쓰지 않고 서버 설정값으로 분리한다.

| 설정값 | 현재 값 | 비고 |
| --- | --- | --- |
| 데드라인 | 운동 시작 1시간 30분 전 | 임시 |
| 체크인 열림 | 시작 10분 전 | 사전 알림도 이 시점 |

| 매너온도 시작값 | 36.5°C |  |

## 1. 계정·회원가입·프로필

로그인은 이메일+비밀번호와 카카오 두 가지이고, 운동 수준(프로필 기록)은 전부 선택 입력이다.

### 로그인

- 이메일+비밀번호 로그인. 별도 아이디는 없다.
- 카카오 로그인: 처음 로그인하면 회원가입 정보 중 이메일·비밀번호를 뺀 나머지(이름·닉네임·성별)를 입력하고 프로필 설정(2b)으로 간다.
- 로그인 상태 유지를 켜면 앱을 다시 열어도 로그인이 유지된다. (안드로이드 개발하며 별도 추가 기능)
- 비밀번호 찾기는 메일 발송이 필요해서 이메일 인증과 함께 추후 구현한다.

### 회원가입

- 필수: 이름, 닉네임(중복 불가 · 모임에서 보이는 이름), 이메일(중복 불가), 비밀번호(영문·숫자·특수문자 조합 8자 이상), 성별.
- 이메일 인증은 추후 추가한다. 지금은 형식 검사와 중복 검사만 한다.

### 프로필(운동 수준)

- 선호 종목(복수), 종목별 기록, 활동 지역을 받는다. 모두 건너뛸 수 있고 나중에 수정한다.
- 운동 수준은 서로의 위치를 가늠하는 지표일 뿐이다. 미설정이거나 모임 기준과 맞지 않아도 신청·참여를 막지 않는다.
- 기록은 헬스 모임 개설(내 기록 표시), 검색 기준 기본값, 기준 일치 판정, 신청 시 호스트에게 전달하는 정보에 쓰인다.

| 종목 | 항목 | 입력 값 |
| --- | --- | --- |
| 헬스 | 가슴 | 벤치프레스 1RM (kg) |
| 헬스 | 등 | 맨몸 턱걸이 연속 최대 횟수 (회, 0회 가능) |
| 헬스 | 하체 | 스쿼트 1RM (kg) |
| 헬스 | 어깨 | 오버헤드 프레스 1RM (kg) |
| 헬스 | 팔 | 숙련도 초급 / 중급 / 고급 |
| 러닝 | 평균 페이스 | 분'초" / km (3km를 대화하며 달릴 수 있는 속도) |
| 등산 | 성향 | 취미 / 전문 |

활동 지역의 쓰임새(예: 위치 권한이 없을 때 지도 첫 화면 중심)는 아직 정하지 않았다(제거할 것) . 조건 설정은 처음에 모두 미설정이므로 위치 조건의 기본값으로는 쓰지 않는다.

## 2. 탐색(지도·리스트)

탐색은 검색 영역 안의 모임을 지도 핀과 하단 카드 리스트로 동시에 보여주고, 핀은 모임 장소의 지번 단위로 묶는다.

### 검색 영역

- 위치 조건이 없으면 현재 지도 화면 범위가 검색 영역이다. 지도를 옮긴 뒤 '이 지역 재검색'을 누르면 새 범위로 다시 불러온다.
- 위치 조건(구·동 또는 현재 위치 반경)이 있으면 그 영역이 고정된다. 지도를 움직여도 결과는 그대로다.
- 위치 조건이 있을 때 '이 지역 재검색'을 누르면 위치 조건이 풀리고 지도 범위 기준으로 바뀐다. 다른 조건은 유지한다.

→ 지도 이동 이벤트 있을 때마다 API 호출하는 방향도 고려 (논의 필요)

### 핀

- 모임 장소 좌표의 **지번**(지도 API가 주는 값)이 같은 모임은 핀 하나로 묶고 모임 수를 표시한다. 묶인 핀을 누르면 그 지번의 모임 리스트가 나온다.
- 같은 지번 안에서의 구분(같은 건물 n층, 공원의 다른 출입구 등)은 호스트가 개설 때 적은 상세주소를 보고 사용자가 판단한다. 배달앱의 상세주소와 같은 방식이다.
- 지도에는 모집중~~·마감 모임만~~ 나오고 진행중·종료·취소 모임 (+모감 모임) 은 빠진다.

### 리스트·찜

- 카드에는 종목, 내 위치에서의 거리, 제목, 장소·일시, 호스트 닉네임·매너온도, 확정/정원을 보여준다. 기본 정렬은 거리순이다.
- 모임을 찜하고 해제할 수 있고, 상단 '찜' 칩으로 찜한 모임만 볼 수 있다. 찜에는 따로 알림이 없다.

## 3. 조건 설정(검색 필터)

처음에는 모든 조건이 미설정(=전체)이고, 사용자는 원하는 조건만 골라 적용한다. '초기화'를 누르면 다시 모두 미설정이 된다.

| 조건 | 규칙 |
| --- | --- |
| 종목 | 하나를 고른다. 미설정이면 모든 종목. '기준'은 종목을 골랐을 때만 설정할 수 있다. |
| 날짜·시간대 | 날짜 하나 + 시간대(00–06, 06–12, 12–18, 18–24) 또는 직접 고른 시간 범위. 모임 **시작 시각** 기준이다. 시간대 복수 선택 여부는 복수 가능 |
| 기준 | 종목별로 다르다. 아래 참고 |
| 위치 | ~~구·동 하나 + 현재 위치 반경(1 / 3 / 5km) or 구·동 하나. 고르면 검색 영역이 고정된다(2장)~~ → 구·동 하나만 선택 |
| 상세 조건 · 성별 | 모임의 성별 조건(누구나 / 여성만 / 남성만)으로 거른다 |
| 상세 조건 · 매너온도 | 호스트 매너온도 하한(30 / 50 / 70°C 이상). 호스트 기준 |

### 헬스 기준

1. **운동 부위**(여러 개): 고른 부위를 **모두 포함하는** 모임만 나온다(AND). 모임에 다른 부위가 더 있어도 된다.
    - 예) '가슴·팔' 선택 → '가슴·등·팔' 모임 포함, '가슴' 모임 제외
2. **기준 설정** 스위치(기본 OFF): 켜면 부위별 수준 범위를 정한다. 부위를 먼저 골라야 켤 수 있다.
    - 켰을 때 초기값은 내 프로필 기록 기준: 중량 ±10kg, 턱걸이 ±2회, 팔은 내 숙련도 그대로. 사용자가 범위를 바꿀 수 있다.
    - 내 기록이 없는 부위는 범위가 비어 있고 직접 정한다.
    - 검색 결과: 고른 부위 중 **하나라도** 모임 기준이 내 범위 안이면 포함한다. 그래서 '일부만 맞아요' 모임도 나온다.
    - 호스트가 기록을 숨긴 부위는 비교할 수 없으므로 '범위 안'으로 치지 않는다.

### 러닝·등산 기준

- 러닝: 페이스 범위. 기준을 켜면 페이스 초기값은 내 페이스 ±30초
- 등산: 취미 / 전문. 기준을 켜면 내 성향이 초기값이다.

## 4. 모임 개설·수정·취소·삭제

호스트는 확정 참가자로 정원에 포함되고, 확정 참가자(호스트 제외)가 생기면 핵심 정보는 바꿀 수 없다. (제목, 상세주소, 설명만 수정 가능)

### 개설 입력

| 항목 | 규칙 |
| --- | --- |
| 종목 | 헬스 / 러닝 / 등산 중 하나 |
| 제목 | 필수 |
| 날짜·시작 시각·진행 시간 | 필수. 종료 시각 = 시작 + 진행 시간. 데드라인이 미래여야 하므로 시작은 지금부터 1시간 30분 이후만 고를 수 있다 |
| 기준 · 헬스 | 운동 부위 1개 이상 + '내 기록 표시' ON/OFF |
| 기준 · 러닝 | 거리(km) + 호스트 본인 페이스 한 값 |
| 기준 · 등산 | 취미 / 전문 |
| 장소 | 장소 검색 또는 지도에서 집결지 지정(러닝·등산처럼 넓은 장소). 좌표·주소·지번을 저장하고 상세주소는 선택 |
| 정원 | 헬스 2\~3명, 러닝·등산 2명 이상(호스트 포함) |
| 성별 | 누구나 / 여성만 / 남성만. 호스트 성별과 다른 성별 제한은 고를 수 없다 **(가정)** |
| 설명 | 선택, 최대 300자(300자는 임시값) |
- 헬스 '내 기록 표시'를 켜면 개설 시점의 프로필 기록을 모임에 복사해 저장한다. 이후 프로필을 바꿔도 이 모임의 값은 그대로다. 기록이 없는 부위는 표시되지 않는다.
- 모임 상세에는 저장된 기록을 **범위**로 보여준다: 중량 ±10kg, 턱걸이 ±2회. 예) 벤치프레스 80kg → '가슴 70–90kg'. 팔·러닝·등산은 값 그대로 보여준다.
- 같은 시간에 개설하거나 신청한 모임이 있어도 서비스에서 막지 않는다. 겹쳐서 생긴 노쇼 등 불이익은 본인이 진다.
- 모임개설 도중 임시저장은 없는걸로

### 수정

- 확정 참가자 0명(호스트만): 모든 항목을 바꿀 수 있다.
- 확정 참가자 1명 이상: 제목·설명·상세주소만 바꿀 수 있다. 일시·장소·정원·성별·종목·기준은 잠기고, 변경 안내는 공지로 한다.
- 수정은 진행중이 되기 전까지만 할 수 있다.

### 취소·삭제

- 확정 참가자 0명: '모임 삭제'. 모임이 사라지고 대기 신청은 자동 거절된다. 매너온도 영향은 없다.
- 확정 참가자 1명 이상: '모임 취소'(방폭). 취소 사유(필수, 100자)를 확정자에게 알림으로 전달하고, 대기 신청은 자동 거절된다.
- 취소 시 호스트 매너온도가 내려간다. 마감 전이든 후든 내려가고, 마감 후가 더 크게 내려간다. **(점수는 미정)**
- 진행중이 된 모임은 취소할 수 없다.

## 5. 신청·수락·마감·나가기

모임은 호스트가 수락해야 들어갈 수 있고, 정원이 꽉 차야만 진행된다. 데드라인(시작 1시간 30분 전)까지 정원이 안 차면 자동 취소된다.

### 신청

- 모집중인 모임에 신청한다. 한마디는 선택(200자 - 임시값)이고, 비워두면 한 번 확인 다이얼로그를 띄운다.
- 호스트에게 가는 정보: 닉네임, 매너온도, 이 종목의 내 기록(없으면 '미설정'), 한마디.
- 서버가 막는 경우: 모집중이 아님, 성별 조건 불일치, 본인이 호스트, 이미 대기·확정 상태.
    - 기준이 맞지 않는 것은 막지 않는다.
- 대기 중에는 언제든 신청을 취소할 수 있고 매너온도 영향이 없다.
- 취소했거나 거절된 신청도 모집중이면 다시 신청할 수 있다.

### 수락·거절·마감

- 호스트가 수락하면 즉시 확정 인원에 반영된다.
- 수락으로 정원이 차면 즉시 **자동 마감**되고, 남은 대기 신청은 모두 자동 거절된다.
- 호스트가 직접 마감하는 기능은 없다. 마감은 항상 '확정 = 정원'일 때만 생긴다.
- 거절(호스트 거절, 마감·취소로 인한 자동 거절) 모두 신청자에게 알림을 보낸다.
- 데드라인 시각에 마감 상태면 그대로 확정되고, 모집중이면(정원 미달) 자동 취소된다. 인원 미달 취소는 누구의 매너온도에도 영향이 없다.

### 나가기(참가자)

| 나간 시점 | 모임에 생기는 일 | 나간 사람 매너온도 |
| --- | --- | --- |
| 모집중 · 확정 후 | 확정 인원 −1 | 영향 없음 |
| 마감 · 데드라인 전 | 마감이 풀려 모집중으로, 데드라인까지 다시 모집 | 하락 |
| 마감 · 데드라인 후 | **모임 전체 취소(방폭)**. 남은 사람은 페널티 없음 | 하락(더 크게) |
| 진행중 이후 | 나가기 없음. 오지 않으면 노쇼 처리 **(시작 시간 이후 10분 지남** **- 기준값은 변경 가능)** | 노쇼 페널티 |

호스트에게는 '나가기'가 없고 '취소'(4장)만 있다. 데드라인 후 나가기 확인 창에는 '지금 나가면 모임이 취소돼요'를 안내해야 한다.

### 참가자 명단 공개

- 호스트: 확정 명단과 신청자 목록을 항상 볼 수 있다.
- 참가자: 본인이 확정 + 모임이 마감 상태일 때만 확정 명단을 볼 수 있다. 마감이 풀리면 다시 가려진다.
- 그 외: 확정/정원 숫자만 본다.

## 6. 모임 상태 전이

모임 상태는 모두 서버가 시간과 인원으로 자동 변경하고, 호스트가 직접 바꾸는 것은 '취소'뿐이다.

!image.png

- 진행중은 운동 시작 시각, 종료는 시작 + 진행 시간에 자동으로 바뀐다. 호스트가 수동으로 종료하지 않는다(호스트 노쇼 등 예외 때문). 종료 후에 더 운동하는 것은 자유다.
- 체크인은 마감 상태인 시작 10분 전부터 열린다(7장).
- 데드라인이 지나면 마감은 더 이상 모집중으로 돌아가지 않는다. 이때 누가 나가면 취소된다.
- 확정 참가자가 0명일 때의 '삭제'는 상태가 아니라 모임을 없애는 것이다.

## 7. 체크인

체크인은 출결앱처럼 시간으로 정상·지각·노쇼를 나누고, 모임 장소 50m 안에서만 성공한다. 호스트를 포함한 모든 확정 참가자가 대상이다. (체크인 기준 거리도 변경될 여지가 있다)

| 시간(운동 시작 기준) | 판정 |
| --- | --- |
| 시작 10분 전 \~ 시작 후 4:59 | 정상 참석 |
| 시작 후 5:00 \~ 9:59 | 지각 |
| 시작 후 10:00까지 체크인 없음 | 노쇼(서버가 자동 처리) |
- 시작 10분 전 이전과 시작 후 10분 이후에는 체크인 버튼이 비활성이다.
- 앱은 기기 GPS 좌표를 보내고, 서버가 모임 장소 좌표와의 거리를 계산해 50m 이내일 때만 성공 처리한다. 범위 밖이면 현재 거리를 알려준다.
- 위치 권한이 없으면 권한 안내 화면을 띄운다.
- 체크인은 한 번만 할 수 있고, 호스트나 참가자가 결과를 고칠 수 없다.
- 노쇼와 지각은 매너온도가 내려간다(지각은 노쇼보다 작게). 활동 내역에는 '참여 완료' 또는 '노쇼'로 남는다.
- 호스트가 노쇼해도 모임은 시간에 맞춰 진행중 → 종료로 바뀐다.
- 체크인한 사람(정상·지각)만 '함께 운동한 사람'이 되어 평가·메이트 신청 대상이 된다.

## 8. 기준 일치 판정

모임 상세의 기준 행(5i)은 내 프로필 기록과 모임 기준을 비교해 '맞아요 / 일부만 맞아요 / 맞지 않아요'를 보여준다. 참고용이라 신청을 막지 않으며, 화면에 표시하지 않기로 할 수도 있다.

| 비교 항목 | '맞음' 조건 |
| --- | --- |
| 헬스 가슴·하체·어깨 | 내 1RM이 모임 기준 범위(호스트 기록 ±10kg) 안 |
| 헬스 등 | 내 턱걸이 횟수가 호스트 기록 ±2회 안 |
| 헬스 팔 | 내 숙련도가 모임 숙련도와 같음 |
| 러닝 | 내 페이스가 호스트 페이스 ±30초 안 |
| 등산 | 내 성향이 모임 성향과 같음 |
- 헬스처럼 부위가 여러 개면: 비교할 수 있는 부위가 모두 맞으면 '맞아요', 일부만 맞으면 '일부만 맞아요'(범위 밖 부위 이름 표시), 하나도 안 맞으면 '맞지 않아요'.
- 비교할 수 없는 부위(내 기록 없음, 호스트가 기록 숨김)는 판정에서 빠진다. 내 기록이 없는 부위에는 '기록 추가'를 보여준다.
- 비교할 수 있는 부위가 하나도 없으면 판정 문구를 보여주지 않는다.
- 판정은 서버가 계산해 모임 상세 응답에 담는다. 검색 필터(3장)와 같은 비교 함수를 쓴다.

## 9. 공지·댓글

공지는 호스트만 쓰고, 호스트와 확정 참가자만 읽고 댓글을 단다.

- 한 모임에 공지를 여러 개 쓸 수 있다. 제목 + 본문(200자 - 미정).
- 수정하면 '수정됨'을 표시한다. 작성·수정 모두 확정 참가자에게 알림을 보낸다.
- 공지 삭제는 호스트만 할 수 있다.
- 댓글은 호스트와 확정 참가자가 쓴다. 답글(대댓글)은 없고, 개발이 끝난 뒤 시간이 남으면 추가한다.
- 댓글 알림: 호스트는 자기 공지에 달린 모든 댓글, 참가자는 자기가 댓글을 단 공지에 다른 사람의 댓글이 달릴 때.
- 모임에서 나간 사람은 공지를 볼 수 없고, 종료·취소된 모임의 공지는 읽기 전용이다.

## 10. 메이트

메이트의 목적은 서로의 모임 활동을 보고, 메이트가 열거나 신청한 모임에 바로 따라 신청하는 것이다. 메이트는 신청 → 수락으로 맺는다.

- 신청 대상: **함께 운동한 사람**만. 같은 모임에서 둘 다 체크인한 적이 있어야 한다. 프로필(15b)의 '메이트 신청' 버튼도 이 조건일 때만 보인다. (같은 모임 참석 여부와 관계없이 누구든지 할 수 있도록 했었나?)
- 받은 사람은 수락 또는 거절한다. 보낸 사람에게는 '신청함'으로 보인다.
- 메이트에게 보이는 활동: 내가 개설한 모임, 신청(대기)·확정한 모임, 지금 진행 중인 운동. 메이트가 아니면 보이지 않는다.
- 메이트의 모임에 신청하는 것도 일반 신청과 같다. 호스트 수락이 필요하고 메이트 우선권은 없다.
- 메이트 알림('모임 개설', '모임 신청')은 유튜브 알림 설정처럼 메이트 한 명마다 켜고 끈다. 기본값은 ON. 와이어프레임에 설정 화면이 없어 추가가 필요하다.
- '함께 운동한 사람' 탭은 체크인 기록 기준이고, 종목 필터와 마지막 운동일을 보여준다.
- 메이트 끊기도 가능함. 이에 관련한 화면 또한 와이어프레임에 없어 프론트개발 하면서 추가바람

## 11. 평가·매너온도

평가는 모임 종료 후 7일 안에 선택적으로 하고, 결과는 곧바로 매너온도에 반영된다. 점수 값은 아직 정하지 않았고 구조만 정했다.

### 평가

- 대상: 종료된 모임에서 체크인한 사람(정상·지각)끼리, 호스트를 포함해 서로. 노쇼한 사람은 평가하지도 받지도 않는다.
- 사람마다 따로, 하고 싶은 사람만 평가한다. 종료 후 3일이 지나면 평가할 수 없다.
- 내용: 판정 1개(좋음 / 보통 / 아쉬움, 필수) + 태그 여러 개(선택) + 한마디(선택, 200자).
- 태그: 좋음·보통은 긍정 태그 묶음, 아쉬움은 아쉬움 태그 묶음을 쓴다. 문구는 표시용이고 목록은 개발하며 정한다.
- 제출한 평가는 수정·삭제할 수 없다.
- 한마디와 태그는 상대 프로필의 후기로 공개된다. '아쉬움' 평가를 공개할지는 정하지 않았다.
- 그리고 추가적으로 모임을 개설한 호스트에게는 평가와 별개로 정상 출석했을 시에 매너온도에 추가점수를 부여한다(호스트에 대한 베네핏)

### 평가에 따른 매너온도 변화

판정마다 기본 점수가 있고, 선택한 태그 한 개마다(문구와 관계없이) 그 판정의 태그 점수를 더한다.

```latex
T = 판정 기본 점수 + (태그 수) * (판정별 태그 점수)
```

| 판정 | 기본 점수 | 태그 1개당 |
| --- | --- | --- |
| 좋음 | + (미정) | + (미정) |
| 보통 | +(미정, 좋음보다 낮거나 zero) | + (미정) |
| 아쉬움 | − (미정) | − (미정) |

### 시스템이 자동으로 내리는 경우

- 노쇼, 지각(노쇼보다 작게)
- 마감된 모임에서 나가기: 데드라인 전(마감 해제), 데드라인 후(방폭 유발, 더 크게)
- 호스트 취소: 마감 전 + 확정자 있음, 마감 후(더 크게)

모든 변화는 서버가 계산하고 사유와 함께 이력(manner_temperature_logs)에 남긴다. 시작값은 36.5°C로 둔다. **(가정)**
